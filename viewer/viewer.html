NAT traversal settings

Both peers must be able to reach the same TURN relay, but they do not have to use the same one. A relay forwards DTLS-SRTP ciphertext, so it cannot see your screen — it does learn both IP addresses and how much data you send.

How this works without a server

WebRTC needs the two peers to exchange an SDP description before a connection exists. That exchange is the only thing a signalling server normally does, and it is just a few kilobytes of text — so it is carried here by copy-paste instead. The offer is deflate-compressed and, with a passphrase, encrypted with AES-256-GCM (PBKDF2-SHA256, 200k iterations). Once the answer gets back to the sender, media flows directly between the two machines; nothing else sees it.

A STUN server may still be used to discover public addresses. There is no TURN relay, so if both peers sit behind symmetric NAT the connection cannot be established at all — that is a protocol limit, not a bug.
